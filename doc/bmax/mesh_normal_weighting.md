# Mesh Data normal weighting

## Controls and precedence

Object Data Properties > Normals contains Weighting Mode, Weight (1-100, default 50), and Threshold (0-10, default 0.01). Weighting Mode defaults to Unweighted, meaning Blender's existing automatic normals (which already use corner angles). The other choices match the Weighted Normal modifier: Face Area, Corner Angle, and Face Area & Angle. Weight 50 is neutral; other values apply the modifier's rank correction with threshold grouping.

Sharp edges and flat faces always define smoothing boundaries. The data panel has no Keep Sharp, Face Influence, or Vertex Group controls. The existing modifier retains those controls and its Face Area & Angle default. Its custom-normal output overrides the automatic data result. Imported and manually edited custom normals are authoritative, including encoded corner normals and float normals on the Point, Face, and Corner domains. A zero encoded normal continues to use Blender's existing geometric basis, so changing the data setting never changes the decoding basis of manual edits.

Settings are per Mesh datablock, shared by objects using that mesh. Evaluated generated meshes inherit the data setting; custom normals written by modifiers remain authoritative. Clearing custom normals makes automatic weighting visible again.

## C++ implementation

`Mesh::corner_normals()` applies weighting to the existing cached automatic normals. `normals_domain()` selects corner normals for weighted smooth meshes. Each smooth fan is processed independently using the existing parallel vertex traversal, with an optional parallel face-area pass. Neutral Weight skips sorting; other weights sort only each fan, rather than the modifier's global face/corner sort. Rank factors are normalized for Weight below 50 to avoid overflowing growing powers. Degenerate contributions fall back to the original automatic fan normal.

No custom-normal attribute is generated by the data setting, and the original geometric normals remain separate for normal editing and encoding. Cache invalidation is shared with normal changes. The RNA update also tags geometry and GPU caches. Parameters are copied to evaluated meshes and generated modifier output. Edit Mode materializes the evaluated BMesh wrapper only for weighted modes so drawing uses the same Mesh corner-normal cache; original-index selection mapping and the direct UV editing path are preserved. This conversion can add significant cost to geometry updates on large meshes, even though unchanged redraws reuse cached data.

## Blend compatibility

Three additional Mesh DNA fields save the settings. Earlier Bmax and official files initialize to Unweighted, Weight 50, Threshold 0.01 by testing field presence, without changing official Blender's version numbers. Official Blender ignores the unknown fields; automatic weighting is not baked, so it shows its ordinary automatic normals. Existing sharp attributes, custom normals, geometry, and standard modifiers remain in Blender's standard formats. Re-saving in official Blender discards Bmax's weighting settings; reopening that file in Bmax uses the defaults. Custom normals and normal modifiers still work in official Blender.

## Performance on the supplied scan

Input: 314,279 vertices, 624,503 triangular faces. All faces were set smooth in memory for the normal comparison; the original file was never saved. Each measurement uses one warm-up and five timed runs, reported as the median. These are synchronous background timings, not interactive FPS. The normal readback includes allocating and copying the complete float32 corner-normal array through RNA into NumPy. Cold runs call `mesh.update()` before timing to invalidate normal caches; cached runs immediately repeat the read. No file load, compilation, rendering, or undo time is included.

| Mode | Cold normals, Weight 50 | Cached readback | Cold normals, Weight 75 | Edit geometry evaluation |
| --- | ---: | ---: | ---: | ---: |
| Unweighted | 3.73 ms | 1.05 ms | — | 1.82 ms |
| Face Area | 5.72 ms | 1.18 ms | 6.99 ms | 24.40 ms |
| Corner Angle | 6.37 ms | 1.13 ms | 7.63 ms | 25.09 ms |
| Face Area & Angle | 6.19 ms | 1.06 ms | 7.18 ms | 26.88 ms |

The Edit column measures `view_layer.update()` after changing one BMesh vertex and calling `bmesh.update_edit_mesh()`. BMesh mutation/normal update and drawing are outside this timed interval. The weighted modes materialize the evaluated mesh, adding about 23-25 ms over the direct Unweighted BMesh path on this input. The subsequent weighted normal calculation and GPU work are additional costs, so these numbers cannot be interpreted as a frame rate. Static redraws reuse the existing normal/GPU buffers. For Object Mode normal recalculation, the measured added cost is about 2-4 ms at neutral Weight and 3-4 ms at Weight 75. Performance may differ with topology, modifiers, undo, hardware, or larger meshes.

All verification scripts, captures, test blends, golden arrays and logs were temporary and removed after validation. Existing inputs, runtime dependencies and compilation caches were retained.

## Direct comparison with an active Weighted Normal modifier

Verified on the same supplied scan on 2026-10-07, with all faces smooth, the same mode, Weight 50 or 75, Threshold 0.01, Keep Sharp enabled, Face Influence disabled and no vertex group. The data-only case has no modifier; the modifier case uses Unweighted in Mesh Data. In both cases a single vertex is moved to the same coordinates for each sample. One warm-up plus five runs are measured per case; the table reports median dependency-graph evaluation plus the first complete evaluated corner-normal readback. Position assignment, BMesh normal/update calls, file loading, undo, rendering and GPU drawing are excluded. These timings describe geometry recalculation, not interactive FPS.

At Face Area & Angle / Weight 50, Mesh Data took 6.84 ms versus 377.92 ms in Object Mode (55x), and 34.00 ms versus 417.49 ms in Edit Mode (12x). Unchanged cached normal readbacks were about 1 ms for both paths. The major savings occur when geometry causes normal/modifier recalculation: automatic data normals avoid copying a mesh, creating and encoding a custom-normal layer, and sorting the entire face/corner population.

The computed normals are not bit-identical to the modifier's encoded custom-normal output. Across these scan cases, the largest 99th-percentile absolute component difference was 0.000346; the largest observed component difference was 0.00943 for Corner Angle / Weight 75. Float calculation/order, threshold grouping near boundaries and custom-normal encoding have different numerical paths. This comparison records those differences rather than asserting pixel-identical scan shading. All normal outputs were finite. The earlier tighter modifier-agreement checks concern the small functional fixture.

The additional comparison scripts, logs and result JSON were removed after recording the results. No source code or original scan was changed by this comparison.
